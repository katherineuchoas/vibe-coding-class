PASSO 1 · PLANEJAR E COMEÇARDiga à IA o que você imaginaFechar passo

Vibe coding é criar com a ajuda de uma IA. Você explica sua ideia com palavras; a IA ajuda a transformar isso em um projeto. Quanto mais claro o pedido, mais perto o resultado fica do que você imaginou.

Um bom pedido conta…

  1. Contexto: quem vai usar e por quê.
  2. Referências: exemplos, links ou imagens.
  3. Visual: cores, estilo e como a tela deve parecer.
  4. Clareza: o que fazer agora e o que deixar para depois.

O caminho em 5 passos

  1. Conte sua ideia com detalhes.
  2. Peça à IA para fazer perguntas.
  3. Monte um plano em etapas.
  4. Peça a outra IA para revisar o plano.
  5. Construa uma etapa por vez e confira o resultado.

Palavras sem susto

Prompt
O pedido que você escreve para a IA.

Frontend
A parte que aparece na tela e onde você clica.

Protótipo
Uma primeira versão para testar a ideia.

A menor versão que já dá para alguém usar.

Uma ferramenta de IA que trabalha nos arquivos do projeto. Você também pode usar outras IAs.

Repositório
A pasta do projeto na internet, com o histórico de mudanças.

PASSO 2 · DADOS E SUPABASEAjude seu projeto a lembrarAbrir passo

Uma tela bonita pode esquecer tudo quando você fecha a aba. O banco de dados é como um caderno organizado: guarda as informações para o projeto encontrar depois.

🍽

Pense num restaurante: a tela recebe o pedido, o backend leva para a cozinha, o banco guarda a informação e a tela mostra o resultado.

Tabela
Como uma planilha: colunas são tipos de informação; linhas são itens.

Backend
A cozinha que organiza pedidos e regras por trás da tela.

Supabase
Um serviço que oferece banco de dados, login e espaço para arquivos.

localStorage
Memória que fica só neste navegador e aparelho.

Migration
Um registro das mudanças feitas no banco.

MCP
Um conector que permite uma IA conversar com uma ferramenta.

O passo a passo da Fase 2

  1. Veja no plano quais informações precisam ficar guardadas.
  2. Escolha e configure o banco de dados.
  3. Crie as tabelas e coloque os dados do projeto.
  4. Troque a memória do navegador pelo banco, sem mudar a tela.
  5. Feche e abra de novo para conferir se os dados continuam lá.
✦

Prompt para entender o caminho dos dados

Use antes de conectar o banco.

Explique em passos simples como uma informação sai da tela, chega ao Supabase e fica guardada.

Use como exemplo [marcar um hábito / editar um perfil / salvar uma tarefa].
Diga quais tabelas seriam necessárias e como posso conferir se funcionou.
Não crie login nem mude a tela nesta etapa.
Avise se faltar alguma informação. Não invente dados.

Conecte seu projeto ao Supabase

Há duas conexões diferentes: o MCP permite que a IA trabalhe com seu banco; a configuração do app permite que a página busque os dados. Este site usa apenas o projeto definido no código. Visitantes não podem escolher outro banco.

  1. Antes de criar o projeto, confirme o custo. No exercício, escolha a organização pessoal e o plano gratuito.
  2. Na ferramenta de IA, abra as conexões, escolha Supabase e autorize somente o projeto desta atividade.
  3. Copie do seu projeto o URL e a chave pública (publishable ou anon) para supabase-config.js.
  4. Use o MCP para criar as tabelas conforme o PLANO.md e confirme que elas aparecem no Supabase.
  5. Troque a leitura do app para buscar esses dados e faça o teste definido no plano.
🔐 Cuide das chaves. A chave pública pode aparecer no navegador, mas nunca use senha nem chave secret ou service_role. Nesta fase, siga o exercício: não crie login nem regras de acesso antes do passo correspondente.
Se as fases não aparecerem: confira se o URL e a chave são do mesmo projeto, se a migration foi aplicada nele e se a tabela public.fases tem linhas. Se precisar investigar, abra o Console (F12) e siga a atividade do Passo 3.

  3. Siga o plano e mova os dados para as tabelas.
  4. Feche a aba, abra de novo e confira os dados.

Exercício 2 · o que muda em cada trilha?

Presença digital

Tabelas: perfil e blocos. Troque a leitura dos dados para buscar no Supabase. Confira carregamento, erro e lista vazia.

Pronto quando: você muda um título na tabela, recarrega e vê a tela atualizada.

Produtividade

Tabelas: tarefas, hábitos, registros, sessões de foco e biblioteca. Leve para o banco os dados que já existiam.

Pronto quando: marca um hábito no celular e vê a mudança no computador.

Recolocação

Tabelas: currículo, vagas, resultados e candidaturas. A chave de IA deve ficar no servidor, como segredo.

Pronto quando: analisa três vagas, fecha o app e depois encontra o histórico.

Ideia própria

Leia o plano, confirme qualquer custo antes de criar o projeto, crie as tabelas previstas e peça à IA para confirmar os nomes.

Pronto quando: o teste definido no seu plano funciona.

Nesta etapa: não crie login nem área de edição. O material também deixa a priorização inteligente para depois. A chave pública e a chave secreta são coisas diferentes: nunca coloque a chave secreta no navegador ou em um repositório público.
PASSO 3 · MELHORAR E CORRIGIRMude uma coisa por vezAbrir passo

Depois de ver o projeto funcionando, novas ideias aparecem. Escolha uma de cada vez. Se algo quebrar, investigue o que aconteceu antes de pedir para a IA consertar.

Quero acrescentar algo?

  1. Liste as ideias e escolha a de maior impacto com menos esforço.
  2. Explique a função, os dados e o caminho na tela.
  3. Peça uma revisão do plano.
  4. Construa só essa função.
  5. Teste a função nova e as telas antigas.

Algo parou de funcionar?

  1. Abra o Inspecionar (F12) antes de repetir o erro.
  2. Faça o erro acontecer de novo.
  3. Anote o que fez, o que aconteceu e o que esperava.
  4. Copie o erro vermelho do Console e veja o status no Network.
  5. Peça para a IA explicar a causa antes de corrigir.
Console: mostra mensagens de erro. Network: mostra pedidos e respostas. O número 200 costuma indicar sucesso; 401 pode indicar que falta login; 403 indica falta de permissão; 404 indica endereço não encontrado; 500 aponta um erro no servidor.

PASSO 4 · LOGIN E SEGURANÇAEscolha quem pode entrarAbrir passo

O login é a última fechadura do projeto. Primeiro, decidimos quais telas podem ser vistas por qualquer pessoa e quais precisam de uma conta. Depois, protegemos a tela e os dados guardados.

Duas perguntas diferentes

Autenticação: confirma quem é você, como conferir o ingresso na entrada.

Permissão: define o que você pode fazer depois de entrar, como escolher em qual área pode circular.

Duas fechaduras

A porta: a tela manda quem não entrou para a página pública.

O cofre: o banco de dados também confere a permissão, mesmo se alguém tentar pular a tela.

Palavras sem susto

Sessão
O navegador lembra que você já entrou.

Rota
O endereço de uma parte do site, como uma área de edição.

Redirecionar
Levar a pessoa para outra página, por exemplo, quando ela não entrou.

Supabase Auth
O serviço do Supabase que cuida de contas e login.

RLS
Regras no banco que limitam quais dados cada pessoa pode ver ou mudar.

Conta de teste
Uma segunda conta para conferir se os dados ficam separados.

Primeiro, separe as telas

Presença digital

A página pública pode ser vista por todas as pessoas. A área de edição é só para você.

Produtividade

Tarefas e hábitos são privados: cada pessoa vê e muda os próprios dados.

Recolocação

Currículo, vagas e análises são privados e ficam ligados à conta da pessoa.

Ideia própria

Liste suas telas e marque cada uma como pública ou privada.

Pergunta para decidir: “Se uma pessoa desconhecida abrir esta tela, tudo bem?” Para este percurso, a leitura das fases é pública; uma futura área de edição deve ser privada.

O passo a passo da Fase 4

  1. Leia o plano e marque o que é público e o que é privado.
  2. Desenhe o caminho: entrar, recuperar a senha, sair e decidir para onde vai quem não entrou.
  3. Peça à IA para proteger a tela e os dados no banco, sem mexer no que já funciona.
  4. No Supabase, crie uma conta de teste em Authentication → Users. Para o exercício, o material orienta ativar a confirmação automática da conta de teste.
  5. Teste manualmente cada caminho: sem login, senha errada e uma segunda conta.
Segurança não é só esconder a tela. A regra do banco também precisa impedir que alguém leia ou altere dados sem permissão. Nunca coloque uma chave secret ou service_role no navegador.

Instale e teste a fechadura

  1. Marque cada tela como pública ou privada.
  2. Revise o plano e construa só a Fase 4.
  3. Crie uma conta de teste no Supabase.
  4. Tente entrar sem conta e com e-mail ou senha errados.
  5. Use uma segunda conta para conferir que ela não vê os dados da primeira.
  6. Confira se o que já funcionava antes continua funcionando.

Na trilha de presença digital, a página pública continua aberta; sem login, a área de edição fica bloqueada.
